Project Mission
You will create a website that projects the professional image you would like recruiters and organizations to see when you introduce yourself.
You will develop the website on your local machine and host it on people.tamu.edu.
Your website will showcase the ability to toggle between multiple styles through CSS and JavaScript to completely change the look, feel, and layout of your website.
See CSS Zen Garden (https://csszengarden.comLinks to an external site.) for an example of the impact of different CSS files on HTML.
This will create a tool for you to share your professional portfolio and information about yourself even outside and beyond this course.


Learning Objectives
You will achieve the following learning objectives:

Explore and gain experience with HTML, CSS, and JavaScript.
Practice configuration management by creating and using a Git repository for your files.
Integrate working in a local development environment and hosting a website on a server, including the ability to transfer files between them.
Provide and receive constructive peer reviews to improve the quality of your work and others.


Project Requirements
General Requirements
You will create and publish a website on people.tamu.edu:.

Your project must be built with only HTML, CSS, and JavaScript.
You cannot use pre-made libraries or templates (e.g., Bootstrap and Tailwind are not allowed).
You may use TypeScript instead of JavaScript since TypeScript is a superset of JavaScript.
Your project must have one HTML file per page and one CSS file for each style.
A total of five required pages.
A total of two CSS files.
Your project must be consistently styled throughout in a way that gives a positive professional image.
Your code must use consistent naming conventions, and must also have consistent use of white space (e.g., indentation, spaces in control blocks, blank lines).
You will use your GitHub account in the class GitHub organization to store your files and for revision control.

Pages Requirements
Your website will also contain at least 5 pages (i.e., one large scrollable page is not acceptable).

Landing page
Gives a positive first impression for a prospective employer or client.
Engages the audience to want to explore more, including interesting information that a prospective employer or organization would want to know.
Demonstrates your unique personality.
Shows how you would fit on someone's team and in their corporate culture.
Is clear and concise, only including information that belongs here.
Labels the page as index.html.

Portfolio page
Describes technical projects you have completed or would like to complete.
Provides interesting details for the audience which may include links to your TAMU GitHub repository for these projects, thumbnails, and descriptions.
Labels the page as portfolio.html.

Qualifications page
Provides your resume in an easily accessible format as a PDF file.
Embeds the file by properly hosting it on Google Drive.
Describes your technical skills in addition to listing them on your resume.
Discusses your technical areas of interest in Computer Science and why.
Labels the page as qualifications.html.

Activities page
Describes ways that either or both:
Gives back to your community (e.g., volunteering, mentoring, other similar service activities).
Highlights your soft skills (e.g., hobbies, interests, other similar pastime activities).
Labels the page as activities.html.

AI-generated page
Leverages generative AI (genAI) fully to create one additional page.
Does not change styles like the other required pages.
Styling will be handled through AI-generated inline CSS instead of from the required external CSS files 
Demonstrates the capabilities of genAI by generating a non-trivially complexx 
The page's contents is not supposed to be about genAI.
Instead, you will utilize genAI to create a non-trivially complex page with designs and contents of your choosing.
Starts with a simple prompt.
Continually adds to the prompt until you are satisfied with the output.
Creates a text box in the new page (genAI services can do this for you) that contains the prompt used by you in the final version of your AI-generated page.
The text box refers to an HTML textbox (see HTML Textbox: A Comprehensive GuideLinks to an external site.).
You can achieve this behavior with multiline text box (i.e., a <textarea>) that is pre-populated with your prompt text.
If your prompt is very lengthy, you should add a scrollbar to the text box. 
Labels the page as genai.html.

Navigation Requirements
Your website must have clear and consistent navigation for your pages.

Internal links
Every page that you create must be linked from some other page.
The “Landing area” page must have links to all other pages.

External links
Minimum of 5 different links to external websites that are relevant to you and the work you are doing.
Note: All external websites must be hosted in unique top-level web domains.
Organically and appropriately placed throughout your project (not on a single “links” section).

Style toggle feature
Completely changes the look, feel, and layout of the website. To accomplish this, do not edit your CSS from the initial design. Start over with a new CSS file, plan the layout, then implement the plan.
Note: Styles limited to functionality such as switching to dark mode, changing background and font colors, or so on are not sufficient.
Uses a toggle button that changes the appearance of the website by alternating between different CSS files with JavaScript.
Note: The AI-generated page is exempt from toggling between alternate styles since it does not dependent on CSS files.
Examples:
See CSS Zen Garden (https://csszengarden.comLinks to an external site.) for an example of the impact of different CSS files on HTML.
See a sample (https://people.tamu.edu/~rob.light/CSCE315/zen.html) to see only the HTML required to build the same CSS Zen Garden website.
Or, use the web developer tools in your browser to turn off CSS on the CSS Zen Garden pages.

Version Control Requirements
Your website must be properly version controlled during development:

Repository code is hosted completely on the class TAMU GitHub organization (i.e., no hosting on personal GitHub repository).
Commits are sufficiently:
frequent (i.e., not sparse in count)
timely (i.e., not made only at the end)
spread out (i.e., not submitted all at once)
Commit messages are sufficiently:
informative (i.e., not generic or repetitive)
understandable (i.e., not gibberish or low-quality)
In addition, include the following supplementary information in your GitHub repository's README file (About the repository README fileLinks to an external site.):

External Links List: a list of at least 5 external website links that are relevant to you and your work and are each from different top-level web domains.
Directly write out the full URL.
State where they are located in your website.
Peer Review Feedback: a description of your peer's review suggestions.
Provide a description of the suggestions provided during lab or elsewhere.
Describe how you incorporated those suggestions to your website.

Resolution and View Requirements
The following assumptions will be made when viewing your resolution:

Varied resolutions on typical desktop displays.
Desktop interface views (i.e., not mobile interface views).
Manual browser zooming of website to fit optimal viewing, if necessary.
